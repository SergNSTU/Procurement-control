# SDS Помощник — расширение для sds.compel.ru (Яндекс.Браузер)

Помощник по «Расчётам заказов»: автоматизирует распознавание пассива
(керамические конденсаторы, постоянные резисторы) после загрузки BOM —
строки вида «0402, 100 nF, 25V, X7R, 10%» или «0402, 10k, 5%», которые
SDS не смог распознать сам.

Расширение **не связано** с WPF-приложением «Procurement Control» и работает
только внутри вашей открытой сессии сайта: отдельный логин не нужен,
пароль нигде не хранится.

## Установка (Яндекс.Браузер)

1. Открыть настройки расширений: в адресной строке `browser://tune` →
   «Расширения» → внизу «Каталог расширений» не нужен — режим разработчика:
   в адресной строке набрать `browser://extensions` (или `yandexbrowser://extensions`).
2. Включить переключатель **«Режим разработчика»** (справа сверху).
3. Нажать **«Загрузить распакованное»** и выбрать папку `sds-extension`
   (ту, где лежит этот README и `manifest.json`).
4. Открыть https://sds.compel.ru/ — справа по центру появится синяя кнопка **SDS+**.

После правок кода: на странице расширений нажать ⟳ на карточке расширения
и обновить вкладку SDS (F5).

## Как пользоваться (распознавание пассива)

1. Откройте расчёт `https://sds.compel.ru/user/carts/{id}` (страница с непаспознанными строками).
2. Нажмите **SDS+** → вкладка «Помощник» → **«Анализировать расчёт»**.
   Панель перечитает расчёт (`UserFolders/GetData`) и покажет строки без позиций.
3. Для каждой строки парсер определит тип и параметры:
   «0402, 100 nF, 25V, X7R, 10%» → конденсатор 0402 100nF 25V X7R ±10%.
   Галочки стоят у уверенных строк (корпус + номинал).
4. **«Найти кандидатов для всех»** — поиск по каталогу (`Search2/Load2`) по
   нормализованным параметрам. У каждой строки — до 6 кандидатов (бренд,
   партномер, склад, цена, срок, MPQ); первый выбран автоматически, можно
   переключить радио-кнопкой. Кнопка «Искать исходную строку» — поиск сырой строкой.
5. **«Применить выбранные…»** — предпросмотр таблицей «строка → что будет
   добавлено → количество», затем «Подтверждаю, применить».
   Выполняются запросы `UserFolders/AddItemsIntoRow` (позиция привязывается
   к существующей строке расчёта). Расчёт после этого перечитывается.

Мутации выполняются **только** по явному подтверждению из п.5. Чтение и поиск — безопасны.

## Вкладка «Лог RPC» (диагностика)

Расширение пишет все запросы сайта к `/api/` (метод, тело, ответ, до 400 записей).
Это нужно, чтобы снять точный контракт кнопки «Распознать», если автоприменение
не сработает:

1. Откройте расчёт с непаспознанным пассивом.
2. Вкладка «Лог RPC» → **«Очистить»**.
3. Вручную нажмите «Распознать» на одной строке, выберите класс
   (конденсаторы керамические / резисторы постоянные) и доведите до результата.
4. «Лог RPC» → **«Скопировать UserFolders»** — пришлите этот JSON;
   по нему контракт будет вшит в автоматику.

Также в помощнике есть «Тест парсера» (14 кейсов разбора пассива) и
«Копировать JSON расчёта» (сырой ответ GetData — на случай, если структура
не распозналась).

## Файлы

| Файл | Назначение |
|---|---|
| `manifest.json` | MV3-манифест; content-скрипты только на `https://sds.compel.ru/*` |
| `content/main.js` | точка входа: инжект логгера, SPA-роутинг, буфер лога |
| `content/inject.js` | MAIN-world: обёртки XHR/fetch (запись RPC-трафика), sessionStorage.ccid |
| `content/sds-rpc.js` | RPC-обёртка (версия API из `data-ver`), извлечение строк из GetData |
| `content/passive-parser.js` | разбор описания пассива + самопроверка |
| `content/panel.js` | панель (shadow DOM): помощник, поиск, применение, лог RPC |

## Ограничения v0.1

- Контракт «распознать» применён по данным main-бандла SDS
  (`AddItemsIntoRow {fid, groupId, rowId, items:[{pnid, hash, qty}]}`).
  Если сервер ожидает другой формат — см. «Лог RPC» выше, правится за одну итерацию.
- Структура ответа `GetData` разбирается эвристикой (несколько вариантов путей).
  Если «Структура не распознана» — прислать JSON расчёта.
- Расширение видит только ваш расчёт, открытый в браузере; чужие (расшаренные)
  расчёты не трогает.
